# /write-test — 테스트 작성

먼저 읽는다: `rules/testing.md`.

## 1. 무엇을 증명할지 한 문장으로
"`PlanService.updatePlan`은 소유자가 아니면 PLAN_002로 막는다"처럼 **행위 하나**를 문장으로 적는다. 문장이 "그리고"로 이어지면 테스트를 나눈다.

## 2. 계층 고르기 (`testing.md` 1번)
| 증명하려는 것 | 계층 |
|---|---|
| 엔티티·enum 규칙 | 도메인 단위 |
| 서비스가 무엇을 조회·저장·발행하고 어떤 예외를 던지나 | 서비스 단위 (Mockito) |
| 상태 코드, 요청 형식 검증, 응답 JSON 모양 | 컨트롤러 슬라이스 |
| 쿼리 결과, fetch join, soft delete 필터, 락, native query | 리포지토리 슬라이스 + Testcontainers |
| 여러 계층을 지나는 사용자 흐름, 트랜잭션 경계, 동시성 | 통합 (안전망) |

가장 아래 계층을 고른다. 같은 규칙을 두 계층에서 검증하지 않는다.

## 3. fixture
- 해당 모듈의 `fixture/{Entity}Fixture`가 있으면 재사용, 없으면 만든다(`testing.md` 5번).
- **엔티티를 mock하지 않는다.** 엔티티가 실제로 가질 수 없는 상태가 필요하다면, 테스트가 아니라 설계를 의심한다.

## 4. 작성
- 이름·구조: `testing.md` 2번 (`{메서드}_{상황}`, `"성공 - …"`/`"실패 - …"`, given/when/then).
- Mockito: `given/willReturn`, `then(...).should()` (3번).
- 단언: AssertJ만 (4번). 예외는 `ErrorCase`까지 검증.
- 컨트롤러: 6번 예시 형식 그대로.
- 시간: `Clock.fixed` (8번).

## 5. 실패를 먼저 본다
- 새 테스트는 **한 번 실패하는 것을 확인**한다(대상 코드를 아직 안 썼거나, 조건을 일부러 뒤집어서). 처음부터 통과하는 테스트는 아무것도 증명하지 않았을 수 있다.
- 옛 코드의 동작을 고정하는 안전망 테스트(characterization test)는 예외다: 현재 동작을 그대로 기록하고, 그 동작이 버그라면 테스트 이름과 주석에 그렇게 적는다.
  ```java
  @DisplayName("현재 동작(버그 R7) - 락 전에 검증해서 삭제된 후보가 대표가 될 수 있다")
  ```

## 6. 실행과 보고
- 해당 테스트 클래스만 먼저: `./gradlew test --tests '…PlanServiceTest'`.
- 그 다음 전체 `./gradlew test`. 결과(통과/실패 수)를 붙인다.

## 체크리스트
- [ ] 테스트 하나에 행위 하나, 성공·실패 분리
- [ ] 엔티티 mock 없음, `@MockBean`·`when().thenReturn()`·JUnit 단언 없음
- [ ] 실패 테스트가 ErrorCase까지 검증
- [ ] 외부 API를 실제로 호출하지 않음
- [ ] 한 번 실패하는 것을 확인함 (안전망 테스트 제외)
