# /gate-review — 답 교정 · 판정 · 기록 (7~8단계)

## 1. 교정
- 사용자 답을 질문별로 나눠 **맞은 부분 / 틀린 부분 / 빠진 부분**으로 구분한다.
- 틀린 부분은 왜 틀렸는지 **반례나 구체적 실패 시나리오**로 보여준다. 정답을 길게 강의하지 않는다.
- 빠진 부분이 핵심(이번 조각의 트레이드오프)이면 짧은 보충 질문을 한 번 던진다.

## 2. 판정
| 판정 | 기준 | 다음 |
|---|---|---|
| **PASSED** | 핵심 "왜"를 자기 말로 설명했다. 사소한 용어 실수는 교정만 | 기록 후 다음 조각 가능 |
| **보충 필요** | 방향은 맞지만 핵심 근거가 비었다 | 보충 질문 1~2개, 게이트는 `OPEN` 유지 |
| **SKIPPED** | 사용자가 한 번 붙잡은 뒤에도 넘어가길 원함 | 미답 항목을 gates.md에 남기고 언제 다시 물을지 적는다 |

대충 넘어가려 할 때 **한 번은 붙잡는다**. 두 번째에는 사용자 결정을 따른다.

## 3. 기록
1. `docs/private/gates.md` — 질문 / **내 답(원문 그대로)** / 교정 / 판정.
2. 공개 설계서 `docs/design/…` — `검증 증거`, `워크스루 요약` 완성. 게이트 내용은 넣지 않는다.
3. `docs/LEARNING_JOURNEY.md` — 항목 하나: **무엇을 했나 → 왜 필요했나 → 핵심 배움 → 다음 질문** (3~5줄, 설계서·ADR 링크).
4. 결정이 있었다면 `/adr`, 막힌 게 있었다면 `/trouble`이 끝났는지 확인.
5. `docs/private/roadmap.md` — 체크박스 갱신 + 상태 블록 `직전 게이트: PASSED|SKIPPED`, 다음 조각 이름 (승인 필요).

## 4. 마무리
`/git-handoff`로 커밋 단위 명령어를 정리해 끝낸다.
