# /adr — 설계 결정 기록

## 언제 ADR을 쓰나
- 되돌리는 비용이 큰 결정: 서비스 경계, DB 분리 방식, 데이터 이관 전략, 동기/비동기 통신, 일관성 모델, API 계약 변경, 도구 채택(ArchUnit·Modulith 등).
- 쓰지 않는 것: 변수명, 리팩터링 세부, 되돌리기 쉬운 구현 선택 → 설계서에만.

## 절차
1. `docs/adr/`에서 가장 큰 번호 + 1. 파일명 `NNNN-{kebab-slug}.md`.
2. `docs/adr/0000-template.md` 형식을 그대로 따른다.
3. **맥락**에는 직전 단계의 고통을 증거와 함께(로그·쿼리·`파일:줄`). **선택지**는 설계 단계에서 제시했던 2~3개를 그대로.
4. **결정**은 결정적 이유 한두 개만. **결과**에는 감수하는 트레이드오프와 "이 결정을 뒤집을 신호"를 반드시 쓴다.
5. 상태는 사용자가 결정했으면 `채택`, 아직 논의 중이면 `제안`.
6. 기존 ADR을 뒤집는 결정이면 새 ADR을 쓰고, 옛 ADR 상태를 `대체됨(→ ADR-NNNN)`으로 바꾼다. 옛 내용은 지우지 않는다.
7. 관련 설계서와 서로 링크한다.

## 공개 레포 주의
ADR은 공개 문서다. 게이트 Q&A·개인 메모·비공개 문서 링크를 넣지 않는다.
