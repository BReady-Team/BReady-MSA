# /piece-start — 조각 시작 (1~3단계)

**이 스킬은 구현하지 않는다.** 사용자가 설계를 결정할 때까지 코드 파일을 만들거나 고치지 않는다.

## 0. 시작 조건 확인
1. `docs/private/roadmap.md`의 상태 블록(`<!-- STATE:BEGIN -->`)을 읽는다.
2. `직전 게이트`가 **`OPEN`이면 시작하지 않는다.** 미답 질문을 다시 보여주고 답을 요청한다. 사용자가 그래도 넘어가겠다고 하면 한 번 붙잡고, 그래도 원하면 `docs/private/gates.md`에 SKIPPED로 기록한 뒤 진행한다.
3. 이번 조각이 로드맵의 어디인지 확인한다. 로드맵보다 앞서가는 인프라(아직 안 온 단계의 Kafka·Gateway 등)는 제안하지 않는다(YAGNI).
4. 관련 문서를 읽는다: `docs/architecture/context-map.md`의 해당 행, 관련 ADR, `docs/private/gates.md`의 미해결 항목(이 단계에서 다시 묻기로 한 것이 있으면 **먼저 묻는다**).

## 1. 왜 지금
- **직전 단계에서 드러난 고통·한계**를 증거와 함께 말한다(실패한 테스트, 로그, 경계 위반 위치 `파일:줄`, 측정값).
- "이 조각이 없으면 다음에 무엇이 막히는가"를 한 문장으로.
- commerce-msa(Phase 1)에서 비슷한 고통이 있었다면 연결한다: "commerce-msa N단계의 ~와 같은 문제인데, 여기선 ~가 다르다".

## 2. 설계
- 선택지 **2~3개**. 각각 방법 / 얻는 것 / 잃는 것 / 되돌리기 비용을 표로.
- **추천안과 결정적 이유 한두 개.**
- 되돌리기 어려운 결정이면 "ADR로 남길 결정"이라고 표시한다(결정 후 `/adr`).
- 사용자에게 결정을 받아야 하는 질문을 명확히 끝에 둔다. 선택지가 분명하면 AskUserQuestion으로 고르게 한다.

## 3. 흐름 미리보기
- 요청/데이터/이벤트가 어떻게 흐르는지 **텍스트 시퀀스 다이어그램**으로, 가능하면 **before → after** 둘 다.
- 트랜잭션 경계(BEGIN/COMMIT), 락, 서비스 경계, 외부 호출을 다이어그램에 표시한다.

## 4. 기록 골격 만들기
- 공개 설계서 골격: `docs/design/{단계}-{순번}-{slug}.md` (본 작업 0단계~). 하네스 조각은 `docs/private/pieces/H{n}-{slug}.md`.
- 골격 섹션: `왜 지금` / `설계(선택지·결정)` / `흐름(before → after)` / `구현 파일` / `검증 증거` / `워크스루 요약` / `알려진 한계`. **게이트 Q&A 섹션은 공개 설계서에 두지 않는다**(→ gates.md).
- `docs/private/roadmap.md` 상태 블록을 `현재 조각: …`, `단계: 2/8 (설계 결정 대기)`로 갱신한다(승인 필요).

## 5. 멈춘다
마지막 줄은 항상 사용자 결정 요청이다. 결정을 받기 전에 4단계(구현)로 넘어가지 않는다.
