# 학습일지

> 조각을 마칠 때마다 한 항목씩 쌓는다. 항목은 짧게(3~5줄) 쓰고 상세는 설계서·ADR로 링크한다.
> 형식: **무엇을 했나 → 왜 필요했나(직전의 고통) → 핵심 배움 → 다음으로 이어지는 질문**

## 2026-10-08 · 출발점 — 경계 지도 초안

- **한 것**: 모놀리식 BReady 전체를 코드 수정 없이 분석해 [경계 지도](architecture/context-map.md)를 그렸다. import 그래프, 모듈을 넘는 JPA 연관, JOIN 쿼리, 여러 모듈을 한 트랜잭션에서 건드리는 곳을 전수 조사했다.
- **왜**: 쪼개기 전에 "어디가 엉켜 있는지"를 모르면 첫 추출부터 분산 트랜잭션 지옥에 빠진다.
- **배움**: 패키지 ≠ 바운디드 컨텍스트. `plan`·`place(후보)`·`trigger`는 `category_states` 한 행을 비관적 락으로 함께 수정하는 하나의 덩어리다. 모듈 간 결합 대부분은 "남의 Service 호출"이 아니라 "남의 Repository 직접 주입"이다. 모든 패키지를 서비스로 만드는 게 목표가 아니라, **어디를 쪼개지 않을지 근거를 대는 것**이 핵심이다.
- **다음 질문**: 코어(플래닝)는 하나로 두고 가장자리(Place Catalog → Recommendation → Stats → Identity)부터 떼는 순서가 맞는가? (1단계에서 ADR로 확정)

## 2026-10-12 · 0-1 키 없이 로컬 기동

- **한 것**: 키 없는 기본 `application.yml`을 커밋하고 모든 외부 값을 `${ENV:로컬더미값}`으로 뒀다. 실제 키는 gitignore된 `application-local.yml`(`local` 프로파일)로 분리했다. 상세는 [설계서 0-1](design/0-1-keyless-local-boot.md).
- **왜**: 클론한 그대로는 앱이 뜨지 않았고 `contextLoads`가 실패했다([T-002](TROUBLESHOOTING.md#t-002)). 컨텍스트가 안 뜨면 통합 테스트를 한 줄도 쓸 수 없다.
- **배움**: 설정 값은 호출할 때가 아니라 빈을 만들 때 해석된다. 그래서 한 번도 쓰지 않는 S3 설정이 기동 전체를 막았다. 막힌 곳은 한 겹이 아니었고(S3 뒤에 OpenAI 자동 설정), 우리 스위치(`recommendation.ai.enabled`)는 우리 빈만 끌 뿐 라이브러리 자동 설정은 끄지 못한다. 환경변수는 플레이스홀더를 채우는 재료라서, 프로파일 파일이 같은 키를 값으로 덮어쓰면 쓰이지 않는다.
- **다음 질문**: 테스트는 아직 H2로 돈다. native query와 비관적 락을 쓰는 코드를 H2로 검증했다고 말할 수 있는가? (0-2)

## 2026-10-12 · 0-2 Testcontainers 기반

- **한 것**: 통합 테스트를 H2에서 MySQL 8.0·Redis 7.2 컨테이너로 옮겼다. 공통 베이스 `IntegrationTestSupport`를 만들고 H2 의존성을 지웠다.
- **왜**: native query와 비관적 락 5곳을 쓰는 코드를 H2로 검증했다고 말할 수 없다. Redis는 꺼져 있어도 `contextLoads`가 통과하고 있었다.
- **배움**: 컨테이너를 `static`으로 한 번만 띄우는 이유는 스프링이 컨텍스트를 재사용하기 때문이다. 클래스마다 새로 띄우면 재사용된 컨텍스트가 죽은 포트를 본다. `@ServiceConnection`은 스프링 부트가 자동으로 만드는 연결에만 닿는다. 직접 만든 `RedisConfig`에는 닿지 않아 설정 값을 바꿔 주는 `@DynamicPropertySource`를 썼다. 

## 2026-10-12 · 0-3 핵심 흐름 통합 테스트

- **한 것**: 가입 → 로그인 → 플랜 → 카테고리 → 후보 2개 → 트리거 → 결정 → 전환을 HTTP부터 MySQL까지 진짜로 도는 통합 테스트를 썼다. 실패 3개(401, 403, 409)도 함께.
- **왜**: 단위 테스트와 슬라이스는 계층을 따로 본다. 모듈 경계를 끊기 시작하면 "한 사용자의 흐름이 그대로인가"를 말해 줄 테스트가 필요하다.
- **배움**: 통합 테스트에 `@Transactional` 롤백을 쓰면 커밋이 없어서 커밋 후 리스너가 돌지 않는다. 그래서 비우기로 격리했다. 비동기로 반영되는 통계는 기다려야 보인다. 응답이 돌아온 순간에는 아직 옛 값일 수 있다는 것이 지금 구조의 성질이다
